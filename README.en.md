# ko-sqlguard

[한국어](README.md) | **English**

A deterministic, PostgreSQL-first policy firewall for SQL generated by LLMs.
It parses one statement with sqlglot, applies an explicit table/column policy,
and fails closed before database execution.

**Status:** software API is Stable. Every deployment still requires a qualified
schema policy, a least-privilege database role, statement timeouts, and quotas.
It is not a database sandbox or a substitute for authorization.

## Install

Until the first PyPI release is published, install the verified source package:

```bash
python3 -m pip install \
  "ko-sqlguard @ git+https://github.com/Marker-Inc-Korea/ko-sqlguard.git@main"
```

## Three-minute start

```python
from ko_sqlguard import Guard, GuardPolicy

guard = Guard(GuardPolicy(
    allowed_tables={"orders": ["id", "status"]},
    default_limit=500,
))

result = guard.check("SELECT id FROM orders")
if result.forward_safe:
    safe_sql = result.sql  # may contain an injected/capped LIMIT
else:
    print([item.code for item in result.violations])
```

The CLI checks SQL and prints JSON. It never executes the statement:

```bash
printf 'SELECT pg_sleep(1)' | ko-sqlguard -
```

## Offline schema policy

Compile trusted schema metadata into both an allowlist and table-specific PII
denylist. The library does not discover a live schema or infer labels at runtime.

```python
from ko_sqlguard import compile_schema_policy

policy = compile_schema_policy({
    "customers": {
        "columns": [
            "id",
            {"name": "주민등록번호", "pii_label": "RRN"},
        ]
    }
})
```

## Guarded execution

`execute_guarded` is an explicit DB-API seam. It requires a production
allowlist by default, runs the structural check, optionally runs `EXPLAIN`
cost checks, and only then opens the execution cursor.

```python
from ko_sqlguard import Guard, execute_guarded

execution = execute_guarded(connection, sql, parameters, guard=Guard(policy))
rows = execution.cursor.fetchall()
execution.cursor.close()
```

The caller remains responsible for connection and transaction lifecycle,
read-only roles, authorization, timeouts, and inspecting/masking returned rows.

## Decision contract

- `PASS`: the original SQL is forwardable.
- `TRANSFORM`: only `result.sql`, not the original SQL, is forwardable.
- `BLOCK`: no SQL is returned.
- `result.to_telemetry()` removes SQL text and reasons for safer logging.

The latest repository benchmark measured the configured AST policy on 2,955
deduplicated attack contexts and 3,819 benign read-only queries. Those figures
describe that corpus and scorer, not every production workload. See the
[Korean README](README.md) and `eval/bench_sql_baselines.py` for methodology,
known misses, and reproduction details.
